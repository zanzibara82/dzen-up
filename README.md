# Дзен Рерайтер

Расширение Chrome (Manifest V3) для работы со статьями в редакторе Яндекс Дзена:

- **перевод и рерайт** — выделили текст в редакторе, нажали иконку на панели внизу окна —
  текст переведён и отрерайчен прямо в редакторе, с сохранением заголовков, списков,
  картинок статьи и инлайн-разметки;
- **перелинковка** — ссылки на свои статьи по упоминаниям моделей в тексте (карта статей
  собирается по sitemap сайтов и обходом каналов Дзена);
- **текст по адресу** — панель открывает статью-источник в фоновой вкладке, забирает
  текст без меню и рекламы, показывает предпросмотр и вставляет его в редактор;
- приписка в конце статьи, глоссарий терминов, AI-рерайт через любой OpenAI-совместимый
  сервис или локальную модель (Ollama).

Пользовательская инструкция и описание всех настроек — [src/extension-src/README.md](src/extension-src/README.md).

## Структура

| Путь | Что это |
|---|---|
| `src/extension-src/` | расширение: manifest, фон, контент-скрипт, попап, стили |
| `test/` | наборы проверок (`bash test/run-suite.sh`, свой Chrome и порт на набор) |
| `tools/` | сборка, уборщик тестовых профилей, живые проверки с настоящими ключами |
| `.github/` | CI: на пуш гоняет только юнит-наборы, браузерные остаются локальными |
| `.agent/` | локальные заметки и черновики (`memory/`, `tmp/`, `backup/`) — в git не попадают |

## Команды

Зависимостей нет, `npm install` не нужен.

```bash
npm run ext:build        # собрать папку расширения (..\dzen-rewriter) + zip
npm test                 # все наборы (~10 минут)
npm test -- --only ui    # только наборы с «ui» в имени
```

Код возврата `npm test`: ноль — все проверки зелёные, единица — есть провал или не
просчиталась ни одна проверка. Раньше скрипт завершался последней `echo` и всегда
давал ноль, поэтому для CI «упало» и «прошло» выглядели одинаково успешно.

Юнит-наборы (`docs`, `reliability`, `links`, `channels`, `fetch`) гоняет и GitHub
Actions — [.github/workflows/unit-tests.yml](.github/workflows/unit-tests.yml), на
каждый пуш и pull request. Браузерные наборы в CI нарочно не входят: 17 запусков
Chrome с портами 8787–8799 на свободном раннере зелёными не бывают, полная
регрессия остаётся локальной.

## Профили тестов и диск

Каждый браузерный набор поднимает свой Chrome в профиле `%TEMP%\dzr-test-profile-<набор>`.
Флаги запуска собираются в одном месте — `PATHS.chromeFlags()` (`test/paths.cjs`): они
обязаны запрещать фоновые загрузки и обновления компонентов, иначе Chrome докачивает в
профиль «дополнения» (одно приносит 1,1 ГБ), а назад эти файлы не отдаются — удаление
блокирует ОС, остаётся только руками. Сторож в `test/test-docs.cjs` следит, чтобы каждый
харнесс стартовал именно через `chromeFlags()`.

Профили переиспользуются между прогонами — это экономит время на каждом наборе, но они
раздуваются: один `dzr-test-profile-mocks` дорастал до 2,4 ГБ, весь набор — до 6,1 ГБ.
Поэтому полный зелёный прогон в конце сносит постоянные профили (`tools/clean-profiles.cjs
--wipe-persistent`); следующий прогон соберёт их заново. Частичный или упавший прогон
профиль оставляет нарочно — по нему разбираются, что именно сломалось. Для отладки одного
набора в несколько запусков есть `DZR_KEEP_PROFILES=1 npm test`: ничего не удаляется, даже
когда прогон полный и зелёный.

Занятый профиль больше не ждёт молча. `PATHS.testProfile()` перед стартом проверяет, не
держит ли папку живой Chrome от прерванного прогона: второй Chrome с тем же
`--user-data-dir` передаёт запуск первому и выходит сам, харнесс остаётся с мёртвым
каналом CDP и ждал 40 повторов по 30 секунд. Теперь это мгновенная ошибка с названием
папки и советом закрыть окно.

Известный flaky: наборы `test-format.cjs` в плотной серии прогонов иногда теряют
выделение — проверка видит «Ничего не выделено» и падает на «текст переведён». В
изолированном прогоне тот же набор зелёный подряд, так что это состояние окна, а не
код расширения.

## Ключи API

Ключи (AI, перевод) вводятся в настройках расширения и лежат только в хранилище браузера.
В файлы репозитория и в коммиты ключи не попадают; живые проверки в `tools/` читают их
из профиля браузера или переменной окружения.

## Версия

Номер версии живёт в [src/extension-src/manifest.json](src/extension-src/manifest.json).
