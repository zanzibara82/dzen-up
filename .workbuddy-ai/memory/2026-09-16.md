### Потом — постоянный набор, без сети

Разовую проверку нельзя держать в наборе (сеть = мигание), поэтому лента канала
отдаётся **мок-сервером**. Адрес API зашит в код как `dzen.ru`, в отличие от карты сайта,
которую задаёт пользователь, поэтому `prepareTestExtension()` в `test-linkify.cjs`
**подменяет строку `CHANNEL_API`** в копии `background.js` на мок-сервер — тем же
принципом, каким карта сайта отдаётся с localhost.

Подмена ищет точную строку и **падает, если не нашла**: молчаливая подмена превратилась бы
в «тест прошёл, а на самом деле ходил в интернет».

Сценарии: **8** — источник канал (ссылки ведут на статьи канала, чужая карточка из ленты
отсеяна по `publisher_id`, текст не тронут); **8б** — канал не отвечает (мок отдаёт 500
на `broken-channel`), ссылка ведёт на сам канал, в отчёте сказано, что карту собрать
не удалось. Набор вырос 34 → **47 проверок**.

## Ошибка: заголовок статьи канала не доходил до отчёта

Нашлась по ходу: в уведомлении вместо названия статьи стоял адрес — `dzen.ru/channelVolvo`.
Причина — одна строка в `content.js`, при раскладке ссылок по абзацам:

```js
placed.push({ block: i, anchor: link.anchor, url: link.url, kind: link.kind });
```

`title` не переносился. Заголовок находился при подборе, ехал из фона (`links.push({…, title})`),
и терялся на последнем шаге — в панели. То есть **задокументированное поведение
(«в отчёте ссылка на статью канала подписана её заголовком, а не id») не работало**,
и в README это было написано зря.

Лечение: `title: link.title` в `placed.push`. Теперь в отчёте:

```
Volvo XC40  → Volvo XC40: честный отзыв после 100 000 км
Scania T143 → Scania T143 — почему её до сих пор покупают
```

Проверка добавлена («в отчёте заголовок статьи, а не адрес») — она и была красной до правки.

Почему не ловили раньше: юнит-тест проверял `links[].title` (там всё на месте), а тест
в браузере до этой правки канал не запускал вовсе. Стык «фон отдал → панель показала»
снова остался без присмотра — тот же класс ошибки, что и вчера.

## README врал про доступ к каналу (и молчал про лимит обхода)

Повод: после правки «заголовок в отчёте» осталось проверить, нет ли в README ещё
таких же утверждений, которые код не выполняет. Нашлись два.

**1. Кнопка доступа к сайтам приписана каналам.** README в трёх местах утверждал,
что доступ к `dzen.ru` выдаётся кнопкой «Разрешить доступ к сайтам» (шаг 2 «Как это
работает», раздел про каналы, раздел «Приватность»). На самом деле `https://dzen.ru/*`
лежит в **обязательных** `host_permissions` рядом с `zen.yandex.ru` и выдаётся при
установке: контент-скрипты и так работают только на Дзене. Кнопка нужна **только**
для доменов из списка сайтов — их в манифесте заранее не перечислить
(`optional_host_permissions: ["https://*/*"]`).

Заодно поправлены комментарии, которые утверждали то же самое:
- `popup.js` `linkOrigins()` — объяснено, почему `dzen.ru` там всё равно остаётся
  (страховка на случай переезда права в необязательные, тогда каналы подхватят
  общий запрос доступа без отдельной ветки);
- `background.js` `exportChannelMaps` — та же причина у проверки `permissions.contains`.
  Обе проверки сегодня **недостижимы** (для обязательного права `contains` всегда true),
  но пусть остаются: иначе при смене манифеста пользователь получит непонятную сетевую
  ошибку вместо внятной.

**2. Лимит обхода нигде не назван.** `CHANNEL_MAX_PAGES = 6` (≈20 статей на страницу)
и `CHANNEL_MAX_ARTICLES = 300` — то есть в карту попадает ~120 статей. Проверено
живым запросом к `dzen.ru/api/v3/launcher/export`: **19–20 карточек на страницу**,
порядок строго **от новых к старым** и внутри страницы, и на стыках (`publication_date`
убывает: стр.1 1789484935…1789016470 → стр.2 1788964635…1788412783 → стр.3
1788326218…1787827519). Значит формулировка «~120 самых свежих» — точная, а не
догадка. Лимит дописан в README (новый абзац «Сколько собирается»), в таблицу настроек
и в подсказку попапа.

## Приём на будущее

**Проверять README против манифеста и констант, а не против памяти.** Оба вранья —
одного рода: текст описывал «как было бы удобно», а не «как в коде». Дешёвая проверка:
`grep -n "Разрешить доступ" README.md` → сверить с `host_permissions` в `manifest.json`;
`grep -n "MAX_PAGES\|MAX_ARTICLES" background.js` → убедиться, что лимит назван в README.
Утверждение о порядке ленты («самые свежие») стоит проверять живым ответом API, а не
рассуждением: `publication_date` в карточке есть, сортировка видна сразу.
