# Дзен Рерайтер — заметки по проекту

Chrome MV3: рерайт статьи в редакторе Дзена на месте (вставить → выделить → иконка внизу → текст заменён с
сохранением разметки), **перелинковка** (ссылки на свои статьи по упоминаниям моделей, текст не меняет) и
**подбор картинок** (Яндекс / Pixabay / Openverse). Детали по дням — `YYYY-MM-DD.md`; приёмы тестирования —
скилл `chrome-extension-cdp-test`, тематические — `html-roundtrip-markers`, `dzen-platform-api`,
`docs-code-consistency`.

## Файлы и команды
- Продукт — `src/extension-src/` (= папка расширения); `test/` (`test-*.cjs`, моки, `run-suite.sh`);
  `tools/build-extension.cjs` → `..\dzen-rewriter` + zip. Зависимостей нет — `npm install` не нужен.
- `npm run ext:build` | `npm test` — **22 набора, ~10 мин**, по **собранной** папке, свой порт 8787–8799 и свой
  Chrome на набор; `DZR_EXT=...` — другая папка. Итог: **1187 проверок, 0 провалов**.
- **Полный прогон писать целиком** (`bash test/run-suite.sh > лог 2>&1`), а не хвостом: лог через
  `tail -40` уже стоил лишних десяти минут разбора — провалы были, а какой набор их дал, узнать неоткуда.
- **Хозяин работает в Яндекс Браузере** (не в Chrome): профиль
  `%LOCALAPPDATA%\Yandex\YandexBrowser\User Data\Default`, расширение там
  `lccpjhkoloofdihmnpkjhgklgahackib` из папки `..\dzen-rewriter`. Настройки человека читаются из
  профиля (leveldb) — приём в скилле `chrome-extension-cdp-test`.
- Живые проверки, которым нужен ключ (в общий прогон не входят): `tools/live-rewrite-check.cjs`
  (AI-рерайт) и `tools/live-pixabay-check.cjs` (Pixabay). Ключ — только из профиля или переменной
  окружения, в файлы и в вывод не попадает.
- **Указание хозяина: после задачи — только затронутые наборы, полный прогон — в конце.**
  `bash test/run-suite.sh --only ui,popup` (`--list`); частичный прогон сам называет себя частичным. Юнит-тест
  умеет читать источник: `node test/test-images.cjs src/extension-src` (иначе — собранная папка).
- Временные папки с **постоянными** именами: копии `test-ext-<набор>` в `.workbuddy-ai/tmp`, профили
  `dzr-test-profile-<набор>` в temp; уборщик — `npm run clean:profiles[:dry]`. **Уборщик читает и
  `test/`, и `tools/`** (профили живых прогонов `liverw`/`livepb`/`probeperm` — не лишние) и
  **исключает свой файл** (в его же комментарии есть `testProfile("<tag>")`). Копии расширения он не
  чистит — их убирают руками, имена старых несут pid и время. Часть папок отдаёт `EPERM` и на
  удаление, и на переименование (снимает перезагрузка) — не выдумывать обходов.
- **`_moved-to-test` в `tmp` не мусор:** старые редакции тестов и моков от 13.09, отличаются от
  нынешних. Хозяин спрошен, ответа пока нет.
- **Состояние профиля файлами не сбросить** (`EPERM`): чистит прогон — `PATHS.clearStorage(c, extId, extPath)`
  **выгружает расширение и грузит заново** (`Extensions.uninstall` + `loadUnpacked`), потом `sync.clear()` +
  `local.clear()` во всех 14 браузерных наборах и **падает** при неудаче. Без перезагрузки Chrome поднимает
  service worker **со скриптом прошлого прогона** — правки `background.js` проходят мимо браузерных проверок;
  `chrome.runtime.reload()` не годится (выгружает расширение насовсем).
- **Версия расширения — 1.1.1** (три источника картинок + кэш ответов); папка `..\dzen-rewriter`, zip
  `dzen-rewriter-v1.1.1.zip`.

## Конвенции
- **Всё по-русски** (UI, комментарии, ошибки, README); комментарии — «почему», не «что».
- **Хранилища:** `sync` — только мелкое (**8192 Б/ключ**, длинное теряется молча); глоссарий, ключи, списки
  ссылок — в `local` (`LOCAL_KEYS`).
- **Разметка — маркерами** `[[n]]…[[/n]]`: узел несёт свою цепочку обёрток, соседние сегменты склеиваются по
  исходному узлу (`chainSrc` → `joinSegItems`). **Перелинковка статью не переписывает:** ссылка идёт круговым
  рейсом (`linkify`); не первый абзац, не соседние, не заголовки/подписи; не нашли — не трогаем.
- **Промпты AI-рерайта — только в `presets.js`**, дефолт продублирован в `DEFAULTS.aiPrompt` (сторожит
  `test-reliability.cjs` §15). Поля: `id`, `name`, `short` (≤8), `hint`, `prompt`.
- **Не переводим уже целевой язык** (`looksLikeTargetLang`, сомнение → переводим); пропуски → `stats.skipped`.
  **Уведомление одно:** `toast()` дважды подряд затирает первое. Поэтому **предупреждение едет в то же
  уведомление, что и результат** (`warn` под статистикой), а не отдельным: отказ AI, показанный отдельно,
  мгновенно сменялся на «✅ Готово» — человек видел успех там, где текст переписал встроенный рерайтер.
  В предпросмотре (там итогового уведомления нет) причина идёт в `meta` и в статус.
- **Операция без смены текста — свой откат** (`restore: true`). **Настройку, меняющую документ, подключай
  опцией вызова, а не чтением `S`** — иначе протечёт в перелинковку (`stripLinks`: `keep|drop|off`).
  **Приписка — свой текст, не перевод:** `S.signature` + `S.signatureText` в `run()` мимо переводчика
  (`isArticleTail` — блок последний; в `contents` — `<br><br>`).
- **README сторожит тест, а не память** (`test-docs.cjs`): числа — **из кода**, у каждой настройки из
  `DEFAULTS` — фраза в README (`SETTING_DOC`), метки таблицы — дословно в `popup.html`, `LOCAL_KEYS` — против
  обещаний про `sync`, права — против `manifest.json`. Новую настройку в `DEFAULTS` пиши **ровно с двумя
  пробелами** (так её читает парсер) и сразу добавляй в `SETTING_DOC`/`LOCAL_DOC` и README.

## Картинки: три источника
- **Выбор — `imgSource`** (`yandex` | `pixabay` | `openverse`), реестр `IMG_SOURCES`, `imgSourceInfo` сводит
  незнакомое значение к Яндексу. Ключи: `imgKey` + `imgFolder` (Яндекс), `pixabayKey` (Pixabay), Openverse —
  **без ключа**; все в `local`, сам выбор в `sync`.
- **Горизонталь обязательна:** Яндекс — `IMAGE_ORIENTATION_HORIZONTAL`, Pixabay — `orientation=horizontal`,
  Openverse — `aspect_ratio=wide`; `horizontalOnly(items)` режет вертикаль только когда размеры есть (иначе
  пропускает — пустая панель неотличима от поломки).
- **Все ответы — к одному виду** `{url, title, width, height, credit, creditUrl}` (поля добавлены, ничего не
  заменяя). `findImages` отдаёт `{images, query, source, notice}`; в окне — подпись под плиткой и памятка
  (`IMG_NOTICE`), памятку чистим вместе с плитками (иначе переживёт неудачный поиск).
- **Права:** Яндекс — поиск, лицензия не наша; Pixabay — **прямую ссылку на их CDN оставлять нельзя**
  (картинку перезалить в Дзен) + кредит; Openverse — свободные лицензии, подпись сохранить в статье.
- **Ответы кэшируются 24 ч** (`dzrImages` в `local`, ключ — источник + фраза + число картинок, потолок
  `IMAGE_CACHE_MAX`): это условие Pixabay, а не оптимизация. Панель говорит «Из кэша», кнопка в настройках
  (теперь просто **«Очистить кэш»**) чистит и переводы, и наборы. `findImages` отдаёт `cached`, и его обязан
  пробрасывать обработчик сообщения — иначе панель врёт.
- **Яндекс платный: 915 ₽ / 1000 запросов**, **1 запрос = `IMAGE_COUNT` = 12 картинок** → ≈0,92 ₽ за фразу;
  поэтому `tries: 1` у Яндекса и у кнопки проверки, у бесплатных — `tries: 2`. Ключ — AI Studio → «Создать
  API-ключ» (сервисный аккаунт `search-api.webSearch.user`, scope `yc.search-api.execute`); `imgFolder` — ID
  каталога; грант 4000 ₽/60 дней — только с привязанной картой. Лимиты: Pixabay 100/мин на ключ (кэш ответов
  24 ч обязателен), Openverse 20/мин и 200/день. Enum — **только в полной форме** (`SEARCH_TYPE_RU`); право на
  домен обязательно (у searchapi нет CORS).
- **Раскладка — лестница долей `IMAGE_SLOTS = [0, 0.5, 0.9, 0.25]`** (обложка / середина / почти конец /
  между обложкой и серединой), `IMAGE_MAX_IN_ARTICLE` = её длина (следит тест). Доли — **по блокам**
  (`topBlocks`, заголовки пропускаются), место **не зависит от каретки**; счёт — **по узлам документа**
  (`countOurImages`): удалил — место освободилось, чужие картинки автора в лимит не идут.
- **Chrome на границе блоков роняет блочную обёртку:** `<p><img></p>` становится строчкой внутри соседнего
  блока. Позиция честно называется «перед блоком», форму узла решает редактор, успех проверяем по документу
  (`imageInEditor`). **Окно переставляем после смены содержимого** (`positionNearBar`), иначе плитки тянут его
  за край экрана (сторожит `panelBox`).
- **Проверка ключей кнопкой** (`checkKey`, `kind: "ai"|"images"`): проверяем ровно тот путь, что и работа
  (адрес, заголовок, модель) — потому и всплывает неверное имя модели; ключи — **из полей попапа**
  (`overrides`), без ключа в сеть не ходим.

## AI-рерайт: адрес, права, честная проверка
- **`aiBaseUrl` — адрес ДО `/chat/completions`** (расширение дописывает сам). Неверный адрес умеет
  отвечать **200** с телом-ошибкой (`{"code":500,"msg":"404 NOT_FOUND"}`), поэтому проверка ключа
  обязана смотреть не на код, а на наличие ответа модели в теле — иначе «ключ рабочий» врёт ровно
  тогда, когда рерайт не пойдёт. То же у `aiRewrite`: пустой ответ показывает начало тела (`headOf`).
- **Модели с рассуждением отвечают пустым `content`.** У них текст уходит в `reasoning`, а на
  коротком лимите проверки (`max_tokens: 8`) `content` приходит пустой строкой с
  `finish_reason: "length"` — и проверка отправляла человека чинить **верный** адрес (поймал хозяин
  на `deepseek-v4.1-flash`). Признак «сервис ответил по-настоящему» — структура ответа чат-модели
  (`aiAnswered`), а не непустой текст. При пустом `content` проверка **повторяет запрос с запасом**
  (`AI_CHECK_RETRY_MAX_TOKENS = 256`), и только если текста нет и там — говорит про рассуждение.
  `aiRewrite` в отказе называет `finish_reason: length`.
- **Свой домен надо выдать правами.** В манифесте только `api.openai.com` и `api.openrouter.ai`;
  для чужого адреса права спрашивает **кнопка «Проверить ключ»** (у неё есть настоящее нажатие).
  Без права запрос режет CORS-предзапрос — но **не всегда**: сервис, отвечающий на `OPTIONS`
  заголовком `Access-Control-Allow-Origin`, пропустит запрос и без права (так «проходил» неверный
  путь z.ai). Поэтому «200 на моём адресе» — не доказательство, что адрес верный.
- **`fetchJson` при обрыве сети называет домен и говорит про доступ**, а не отдаёт «Failed to fetch».
- **Локальный AI (Ollama) стоит на машине**: 0.34.2, порт 11434, модели `qwen2.5:7b`,
  `qwen2.5:3b`, `llama3:latest`, OpenAI-путь `/v1/chat/completions` отвечает. **Подключён:**
  в необязательных правах `http://localhost/*` и `http://127.0.0.1/*` (широкий `http://*/*`
  сознательно не берём), `aiOrigin()` в попапе спрашивает доступ и по http — только для своей
  машины, чужой http объясняет отказом. **Одного права мало:** Ollama отказывает по заголовку
  `Origin` (403), лечится `OLLAMA_ORIGINS=chrome-extension://*` — значение **добавляется** к
  умолчаниям, а не заменяет их. Сквозная проверка: 14 проверок, 0 провалов.
- **Своя машина — другой режим работы, а не тот же с другим адресом.** Ключа у неё нет (и пустой
  `Authorization: Bearer ` не шлём вовсе), `qwen2.5:7b` тратит ~40 с на абзац, поэтому:
  `isLocalAiBase` (`localhost`, `127.0.0.1`, `0.0.0.0`, `::1`/`[::1]`, `*.local`) → `aiHasAccess`
  (ключ ИЛИ свой адрес) и **`tries: 1`** вместо 3 попыток (у проверки ключа потолок 120 с: первая
  грузит модель с диска). 10 минут безопасны: обмен сообщениями через `chrome.runtime` держит
  воркер живым, а лимит «5 минут на одно событие» на него не действует.
  Панель и попап считают секунды ожидания, фон шлёт `{type:"progress", stage:"ai", local}`.
- **Потолок запроса растёт с текстом** (`aiTimeoutMs`): база + **150 мс/слово**, предел — облако
  **5 минут** (база 90 с), своя модель **10 минут** (база 300 с). **Таймаут не повторяется** —
  `fetchJson` бросает сразу, иначе три повтора дали бы четверть часа ожидания; повторы остались
  только для настоящих сбоев у облака. Фиксированные 90 с рвали длинную статью на медленной модели.
  **Живая мера — ≈188 мс/слово** (`deepseek-v4.1-flash` на polza.ai, 63 слова за 11,9 с): на
  коротком тексте база перекрывает с запасом, но предел в 5 минут начинает действовать с ~1400 слов,
  и очень длинная статья на медленной модели с рассуждением может в него упереться.
- **Таймаут рерайта объясняется, а не только называется** (`timeoutNote` в `fetchJson` +
  `aiTimeoutNote(text)`): после пяти минут ожидания «таймаут 300 с» читается как «ключ не тот», а
  причина — длина текста и скорость модели. Пояснение собрано **отдельной функцией** и едет опцией
  — иначе его не проверить ничем, кроме пятиминутного ожидания. Слова считает `textWords`.
- **Проверка ключа делает два запроса с разными потолками:** `AI_CHECK_TIMEOUT_MS` = 30 с у
  короткого (8 токенов) и `AI_CHECK_RETRY_TIMEOUT_MS` = 90 с у повтора (256) — повтор больше в 32
  раза и адресован самой медленной модели. У своей машины оба идут с `AI_LOCAL_CHECK_TIMEOUT_MS`.
  Хозяин проверял живьём: **16 проверок, 0 провалов** (`tools/live-rewrite-check.cjs`, настройки
  берёт из профиля Яндекс.Браузера, ключ только маской). Сервис принимает короткое имя модели,
  хотя в списке она с префиксом — предупреждение списка про именование, не про поломку.

## Источники ссылок (механика — скилл `dzen-platform-api`)
- **Сайты:** адрес статьи по `sitemap.xml` (`SITEMAP_MAX_URLS = 5000`), модель ищется в слаге.
- **Каналы Дзена:** модель ищется **по заголовку**, кэш 12 ч в `dzrChannels`, неудачный обход прежнюю карту не
  затирает. **`CHANNEL_MAX_PAGES = 6`** → ~120 статей, лента **от новых к старым**; лимит обязан быть назван в
  README, таблице настроек и подсказке попапа.
- **`dzen.ru` — обязательное право.** Кнопка «Разрешить доступ к сайтам» **каналов не касается** — только
  домены **сайтов** (`optional_host_permissions`). Без доступа `buildLinks` → `err.needPermission`. Выгрузка
  карты — файлом sitemap.xml: заголовки **комментариями** перед `<loc>`, берётся **кэш**, скачивание —
  `<a download>` + blob, **не** `chrome.downloads`.

## Приёмы
Полностью — в скилле `chrome-extension-cdp-test` (там же ловушки проверок и гигиена Chrome). Бэкап перед
чисткой — в `.workbuddy-ai/backup/`: корзины в среде нет, а массовое удаление песочница не пропускает.
